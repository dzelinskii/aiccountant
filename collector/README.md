# Коллектор операций Т-Банка

Забирает операции из личного кабинета Т-Банка и отправляет их в AIccountant как
готовый импорт — его остаётся подтвердить в приложении.

Коллектор работает **на машине пользователя**: банк должен видеть домашний IP и
привычный браузер, а код из СМС человек вводит сам. Возможности коллектора
ограничены не обещанием, а списком из пяти разрешённых адресов
(`src/plugins/tbank/client.ts`): всё остальное клиент отвергает до отправки
запроса.

## Как хранится доступ к банку

Единственный секрет банка — кука сессии, она живёт **только в персистентном
профиле браузера** (`collector/profile/`), где куки шифрует сам браузер
средствами ОС. В конфиг, переменные окружения, файлы и git этот токен не
попадает никогда. Сессия действует около суток; когда она истекает, коллектор
открывает окно входа — телефон и код вводит человек, в форму входа коллектор не
вмешивается.

«Забыть» доступ к банку — отдельная команда: она удаляет профиль целиком,
вместе с кукой сессии.

    pnpm forget

Команда безопасна и до первого входа, и повторно. После неё ближайший сбор
снова откроет окно входа.

## Установка

    pnpm install
    pnpm exec playwright install chromium   # браузер для окна входа, нужен до первого запуска

## Настройка

| Переменная               | Обязательна | По умолчанию            | Значение                                        |
| ------------------------ | ----------- | ----------------------- | ----------------------------------------------- |
| `AICCOUNTANT_URL`        | нет         | `http://localhost:8000` | адрес приложения                                |
| `AICCOUNTANT_TOKEN`      | да          | —                       | API-токен приложения                            |
| `AICCOUNTANT_WORKSPACE`  | да          | —                       | uuid рабочего пространства                      |
| `AICCOUNTANT_ACCOUNTS`   | нет         | `{}`                    | JSON: счёт банка → счёт приложения              |
| `COLLECT_DAYS`           | нет         | `30`                    | за сколько дней забирать операции               |

### Токен приложения

Токен выдаётся из браузерной сессии и показывается **один раз** — при создании.
Он привязан к одному рабочему пространству и отзывается через
`DELETE /api/tokens/<id>`.

    # вход: кука сессии останется в cookies.txt
    curl -sk -c cookies.txt -X POST http://localhost:8000/api/auth/login \
      -H 'Content-Type: application/json' \
      -d '{"email":"you@example.com","password":"..."}'

    # uuid рабочего пространства
    curl -sk -b cookies.txt http://localhost:8000/api/me

    # токен для коллектора
    curl -sk -b cookies.txt -X POST 'http://localhost:8000/api/tokens?workspace_id=<uuid>' \
      -H 'Content-Type: application/json' -d '{"name":"Коллектор Т-Банка"}'

### Идентификаторы счетов

Счета приложения видны в `GET /api/accounts?workspace_id=<uuid>`, счета банка —
в самом коллекторе: запустите его с пустым `AICCOUNTANT_ACCOUNTS`, и он напечатает
список (идентификатор, валюта, название) и ничего не будет собирать.

    AICCOUNTANT_TOKEN=... AICCOUNTANT_WORKSPACE=... pnpm collect

    Счета в банке:
      5f3a...  RUB  Счёт для трат
      9c11...  RUB  Накопительный
      c204...  валюта не распознана  Внешний счёт

Полученные пары подставьте в `AICCOUNTANT_ACCOUNTS`. Валюта счёта банка и счёта
приложения должны совпадать — иначе приложение отклонит импорт.

Счета, валюту которых коллектор не разобрал, в списке остаются с пометкой
«валюта не распознана»: на сбор по остальным счетам это не влияет. У операций
требования строже — операцию с неизвестной валютой коллектор не отправит, а
сообщит об ошибке.

## Запуск

    export AICCOUNTANT_TOKEN=...
    export AICCOUNTANT_WORKSPACE=<uuid>
    export AICCOUNTANT_ACCOUNTS='{"5f3a...":"<uuid счёта приложения>"}'
    pnpm collect

Первый запуск (и первый после истечения сессии) откроет окно браузера на
странице входа Т-Банка и подождёт до пяти минут, пока вы войдёте. Дальше
браузер не нужен — работает обычный HTTP.

В консоль выводятся только идентификаторы и счётчики: сколько операций собрано и
какой импорт создан. Суммы и описания операций не печатаются.

    счёт 4e21...: собрано 137, импорт 8bd0...
    Готово. Подтвердите импорт в приложении.

Если банк пометил часть операций видом, которого мы не знаем, в выводе появится
отдельная строка со счётчиком. Это не ошибка: такие операции импортируются и
остаются видимыми, но повод заглянуть, не завёл ли банк новое значение.

## Повторный сбор не обновляет уже импортированные операции

Дедуп работает по идентификатору операции от банка: повторный сбор за тот же
период считает такие операции дублями и **не трогает** их. Это правильно для
обычной работы, но означает, что новые поля разбора на старые операции не
распространяются задним числом.

Пример: коллектор научился передавать вид операции (перевод, покупка, движение
между своими счетами). У операций, собранных до этого, вида нет — они остались
с `unknown` и считаются тратами. Повторный сбор их не исправит.

Чтобы собрать заново, удалите операции счёта в приложении и запустите сбор
снова. Ручных правок — категорий, заметок, решений «учитывать в статистике» —
это тоже лишит, так что для большой истории лучше смириться со старыми
значениями, чем терять свою работу.
