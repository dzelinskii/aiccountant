# Коллектор операций банка

Забирает операции из личного кабинета банка и отправляет их в AIccountant как
готовый импорт — его остаётся подтвердить в приложении. Поддержаны три банка:
**Т-Банк**, **Сбербанк** и **Альфа-Банк**.

Коллектор работает **на машине пользователя**: банк должен видеть домашний IP и
привычный браузер, а код входа человек вводит сам — в форму входа коллектор не
вмешивается.

## Выбор банка

Какой банк собирать, задаёт переменная `COLLECT_BANK`:

    COLLECT_BANK=sber pnpm collect

Поддерживаются `tbank`, `sber` и `alfa`. По умолчанию, если переменная не
задана, — `tbank`. Неизвестное значение — сразу понятная ошибка со списком
известных банков, а не попытка угадать.

## Как хранится доступ к банку

Секрет банка (кука сессии) не попадает в конфиг, переменные окружения и git.
На диске он живёт в двух местах, и оба стирает команда «забыть»:

- **хранилище секретов ОС** — Credential Manager на Windows, Keychain на macOS,
  libsecret на Linux. Туда коллектор кладёт секрет **любого банка**, отдельной
  записью на банк;
- **профиль браузера** (`collector/profile/<банк>/`), где куки ведёт сам
  браузер, шифруя их средствами ОС.

Разница между банками не в месте хранения, а в том, можно ли обновить сессию
без человека — и причина не в архитектурном вкусе, а в поведении самих банков:

- **Т-Банк.** Кука `psid` короткоживущая и ротируется, но сама сессия в профиле
  живёт долго: коллектор открывает личный кабинет в фоновом окне, и банк по
  живой сессии выдаёт свежую куку. Код нужен, только когда умерла и сессия.
- **Сбербанк.** Обе нужные куки — сессионные, и профиль браузера их не
  сохраняет: проверено живьём — после закрытия окна повторное открытие того же
  профиля не находит ни одной. Обновлять нечего, поэтому истечение сессии
  всегда означает видимое окно входа.
- **Альфа-Банк.** Сессионная кука `GW_SESSION_AO` тоже коротка (по замеру
  ~15–30 минут), фонового обновления в v1 нет. Но профиль браузера помнит
  устройство, и повторный вход — быстрый: банк просит ПИН, а не полный вход по
  СМС. Настоящее продление без человека возможно (у Альфы есть долгоживущие
  refresh-токены OIDC), но это отдельная будущая работа, не v1.

«Забыть» доступ к банку — отдельная команда: она стирает **оба места** сразу
для всех банков — и профиль браузера, и запись в хранилище ОС.

    pnpm forget

Команда безопасна и до первого входа, и повторно. После неё ближайший сбор
снова откроет окно входа.

## Сертификат УЦ Минцифры

Сбербанк **и Альфа-Банк** выпущены через УЦ Минцифры («Russian Trusted Root
CA») — один и тот же корень, которого нет ни в хранилище Windows/macOS/Linux,
ни в браузерах, ни в Node. Без него коллектор не может ни открыть окно входа
такого банка, ни сходить в его API — банк недоступен коллектору в принципе.
Т-Банку этот корень не нужен.

Порядок получения: кеш рядом с профилем (`collector/profile/`) → скачивание с
официальной точки раздачи Госуслуг → **проверка по отпечатку, зашитому в код**
(`collector/src/runner/trust-anchor.ts`). Скачивание — только удобство; доверие
держится на константе в исходниках, а не на том, что пришло по сети. Файл с
чужим отпечатком отвергается и не используется, даже если уже скачан.

Важно, чего коллектор **не делает**: он ничего не устанавливает в системное
хранилище доверия ОС или браузера. Корень подставляется только внутри процесса
коллектора — в HTTP-запросы к Сбербанку и (отдельным флагом) в окно входа,
чтобы штатный Chromium согласился открыть страницу банка. Закрепление ключа в
окне входа получает **только тот банк, которому это нужно** — у Т-Банка окно
входа открывается как обычно, без каких-либо изменений доверия.

Если у вас есть браузер, который несёт этот корень внутри себя (например,
Яндекс.Браузер, Atom), его можно подставить переменной `COLLECTOR_BROWSER`
(путь до исполняемого файла) — тогда закрепление ключа не требуется. Это
запасной путь, а не условие работы.

    pnpm install

| -------------------------- | ----------- | ------------------------ | ----------------------------------------------- |

| `AICCOUNTANT_URL`           | нет         | `http://localhost:8000`  | адрес приложения                                |
| `AICCOUNTANT_TOKEN`         | да          | —                         | API-токен приложения                            |
| `AICCOUNTANT_WORKSPACE`     | да          | —                         | uuid рабочего пространства                      |
| `AICCOUNTANT_ACCOUNTS_TBANK`| нет         | `{}`                      | JSON: счёт Т-Банка → счёт приложения            |
| `AICCOUNTANT_ACCOUNTS_SBER` | нет         | `{}`                      | JSON: карта Сбербанка → счёт приложения         |
| `AICCOUNTANT_ACCOUNTS_ALFA` | нет         | `{}`                      | JSON: номер счёта Альфы → счёт приложения        |

| `COLLECTOR_BROWSER`          | нет         | системный Chromium        | путь к своему браузеру, несущему корень УЦ Минцифры |

### Счета — переменная своя у каждого банка

У каждого банка свой список соответствий счетов: `AICCOUNTANT_ACCOUNTS_TBANK`
для Т-Банка, `AICCOUNTANT_ACCOUNTS_SBER` для Сбербанка. Это осознанно: у
банков разные идентификаторы счетов, и один общий список означал бы, что при
смене банка коллектор молча не найдёт ни одного счёта.

Если пер-банковская переменная не задана, коллектор откатывается на общую
`AICCOUNTANT_ACCOUNTS` — она работает как раньше, для одного банка за раз.
Удобно, пока банк один; с двумя банками стоит перейти на пер-банковские имена.

### Токен приложения

Токен выдаётся из браузерной сессии и показывается **один раз** — при создании.
Он привязан к одному рабочему пространству и отзывается через
`DELETE /api/tokens/<id>`.

    # вход: кука сессии останется в cookies.txt
    curl -sk -c cookies.txt -X POST http://localhost:8000/api/auth/login \
      -H 'Content-Type: application/json' \
      -d '{"email":"you@example.com","password":"..."}'

    # uuid рабочего пространства
    curl -sk -b cookies.txt http://localhost:8000/api/me

    # токен для коллектора
    curl -sk -b cookies.txt -X POST 'http://localhost:8000/api/tokens?workspace_id=<uuid>' \
      -H 'Content-Type: application/json' -d '{"name":"Коллектор банка"}'

### Идентификаторы счетов

Счета приложения видны в `GET /api/accounts?workspace_id=<uuid>`, счета банка —
в самом коллекторе: запустите его с пустым списком счетов для выбранного
банка, и он напечатает список (идентификатор, валюта, название) и ничего не
будет собирать.

    COLLECT_BANK=sber AICCOUNTANT_TOKEN=... AICCOUNTANT_WORKSPACE=... pnpm collect

    Счета в банке:
      card:1111...  RUB  Карта •• 1234
      card:2222...  RUB  Кредитная карта •• 5678

    Задайте AICCOUNTANT_ACCOUNTS_SBER — соответствие счетов банка счетам приложения:
      AICCOUNTANT_ACCOUNTS_SBER='{"card:1111...":"<uuid счёта в приложении>"}'

У Сбербанка единицей счёта служит **карта**: история операций привязана к ней,
а не к счёту в обычном смысле — так её отдаёт сам банк. Кредитная карта
становится отдельным счётом приложения.

У Альфа-Банка наоборот — единица счёта это **счёт** (его 20-значный номер):
история фильтруется по нему, карты к нему привязаны и отдаются последними
четырьмя цифрами. Инвестиционные и металлические счета Альфы коллектор не
собирает — истории операций в понимании приложения у них нет.

Полученные пары подставьте в соответствующую переменную. Валюта счёта банка и
счёта приложения должны совпадать — иначе приложение отклонит импорт.

Счета, валюту которых коллектор не разобрал, в списке остаются с пометкой
«валюта не распознана»: на сбор по остальным счетам это не влияет. У операций
требования строже — операцию с неизвестной валютой коллектор не отправит, а
сообщит об ошибке.

## Запуск

    export COLLECT_BANK=sber
    export AICCOUNTANT_TOKEN=...
    export AICCOUNTANT_WORKSPACE=<uuid>
    export AICCOUNTANT_ACCOUNTS_SBER='{"card:1111...":"<uuid счёта приложения>"}'
    pnpm collect

Первый запуск (и первый после истечения сессии) откроет окно браузера на
странице входа банка и подождёт, пока вы войдёте. Дальше браузер не нужен —
работает обычный HTTP.

**У Сбербанка сессия живёт недолго** — по замерам меньше часа (точнее сказать
нельзя: шаг измерения был часовым). Практически это значит, что окно входа у
Сбербанка будет открываться заметно чаще, чем у Т-Банка, — это ожидаемое
поведение, а не сбой.

**У Альфа-Банка сессия ещё короче** — по замеру ~15–30 минут, так что вход
потребуется часто. Смягчает это быстрый вход: браузер помнит устройство, и
банк на повторном входе просит ПИН, а не полный вход по СМС.

В консоль выводятся только идентификаторы и счётчики: сколько операций собрано
и какой импорт создан. Суммы и описания операций не печатаются.

    счёт 4e21...: собрано 137, импорт 8bd0...
    Готово. Подтвердите импорт в приложении.

Следом печатаются три счётчика, и каждый молчит, когда считать нечего:
операции с нераспознанным видом, траты без подсказки о категории и приходы,
которые банк не дал разобрать подробнее. Ни один из них не ошибка — такие
операции импортируются и остаются видимыми. Это повод заглянуть, не завёл ли
банк новое значение: словари коллектора сверяются с тем, что банк присылал
раньше, и расхождение видно только здесь, на живых данных.

## Возможности коллектора ограничены списком адресов

Коллектор физически не способен обратиться никуда, кроме перечисленных адресов
(`src/plugins/tbank/client.ts`, `src/plugins/sber/client.ts`,
`src/plugins/alfa/client.ts`): всё остальное клиент отвергает до отправки
запроса. Список — проверяемая гарантия, а не обещание: его видно прямо в коде.

Для Т-Банка список состоит из пяти адресов, и все они методом `GET` — методом
на чтение ничего не сломать, и это отдельная, самостоятельная гарантия.

**Для Сбербанка и Альфа-Банка гарантия слабее, и это стоит сказать честно.**
Оба отдают историю методом `POST` (у Альфы из трёх адресов два — `GET`, а
история — `POST`), поэтому метод сам по себе больше ничего не доказывает.
Остаётся более слабое, но по-прежнему проверяемое утверждение: коллектор
обращается только к перечисленным адресам (Сбер — два, Альфа — три), и все они
читающие. Первое можно проверить, прочитав короткий список в коде; второе
требует доверия к тому, что перечисленные эндпоинты не меняют состояние.

## Чего коллектор Сбербанка не собирает

Паритет с Т-Банком, ни больше ни меньше. Сознательно не собираются:

- долг и минимальный платёж по кредитной карте;
- кредиты;
- вклады;
- инвестиции.

Эти данные у банка есть, но класть их в приложении сейчас некуда — нужны
отдельная миграция, модель и интерфейс. Это будущая, отдельная работа.

## Остаток счёта и цифры карты

Вместе с операциями коллектор передаёт остаток счёта, каким его показывает банк,
и последние четыре цифры карт — чтобы в приложении было видно, какой именно счёт
перед вами. Номер карты банк отдаёт уже замаскированным, полного номера у
коллектора нет.

Остаток применяется **при подтверждении импорта**, а не при отправке: иначе
число на экране обновилось бы, пока операции ещё ждут вашего решения. Если
подтвердить старый сбор после нового, остаток не откатится назад — побеждает
более поздний сбор, а не более поздний клик.

**В день без операций остаток не обновится.** Отправлять нечего: запрос импорта
требует хотя бы одну операцию, и заводить отдельный путь ради этого случая
дороже пользы. Поэтому рядом с остатком в приложении показано, **на какой момент**
он верен — число без отметки времени выглядело бы текущим, хотя таковым не
является.

## Повторный сбор не обновляет уже импортированные операции

Дедуп работает по идентификатору операции от банка: повторный сбор за тот же
период считает такие операции дублями и **не трогает** их. Это правильно для
обычной работы, но означает, что новые поля разбора на старые операции не
распространяются задним числом.

Пример: коллектор научился передавать вид операции (перевод, покупка, движение
между своими счетами). У операций, собранных до этого, вида нет — они остались
с `unknown` и считаются тратами. Повторный сбор их не исправит.

Чтобы собрать заново, удалите операции счёта в приложении и запустите сбор
снова. Ручных правок — категорий, заметок, решений «учитывать в статистике» —
это тоже лишит, так что для большой истории лучше смириться со старыми
значениями, чем терять свою работу.
