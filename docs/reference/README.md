# Справочник: что система есть сейчас

Спеки в `docs/superpowers/specs/` описывают **изменения** — что решили и почему,
на свою дату. Этот справочник описывает **состояние**: как система устроена
сегодня.

Расходятся — прав код, а справочник надо чинить.

## Модули

- [identity](identity.md) — люди, workspace, членство, сессии и токены: кто это
  и пускать ли его
- [ledger](ledger.md) — счета, категории, операции, остатки
- [recurring](recurring.md) — регулярные платежи: расписание, срабатывания,
  автопроведение и напоминания
- [imports](imports.md) — приём выписок и собранного коллектором: разбор,
  дедупликация, подтверждение
- [collector](collector.md) — сбор операций из личных кабинетов банков; работает
  на машине владельца, а не на сервере
- [desktop](desktop.md) — десктопное приложение: команды оболочки, окна банков,
  хранилище секретов, доверие к УЦ, вход в приложение и экран «Банки»

Остальные (`ai`, фронтенд) появятся здесь по мере написания.

## Генерируемое

Файлы в [generated/](generated/) созданы из кода и **руками не правятся**:
схема базы, ручки API, словари, границы модулей и таблицы перевода банковских
слов — по документу на банк (`collector-tbank.md`, `collector-sber.md`,
`collector-alfa.md`) плюс общий `collector-mcc.md`: коды торговых точек
приходят от разных банков и живут
в общем модуле, поэтому им место не в файле одного из плагинов.
CI перегенерирует их и падает, если результат отличается от закоммиченного.

Перегенерировать:

    cd backend && uv run python scripts/gen_reference.py
    cd collector && pnpm reference

## Правила ведения

Меняете поведение — правьте документ в том же PR. CI это требует: правка
файла, несущего контракт, без правки `docs/reference/` красит сборку. Список
таких файлов и исключение для тестов (`*.test.ts`) — выражения задания
`docs-gate` в `.github/workflows/ci.yml`; здесь их не пересказываем, чтобы копия
не разошлась с тем, что проверяет CI. Ворота работают только на
pull request; если правка и правда не меняет поведения — метка `docs-not-needed`
на PR.

Утверждение, которое можно проверить, должно проверяться: словари и схема
генерируются, границы модулей стережёт import-linter. Руками пишется только то,
что проверить нечем, — и потому его должно быть мало.
