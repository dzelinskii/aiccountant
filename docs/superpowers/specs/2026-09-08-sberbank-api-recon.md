# Сбербанк — результаты разведки API личного кабинета

Дата: 2026-09-08. Статус: факты собраны, дизайн не начат.

Это **не спека**, а её фактическая основа: что банк отдаёт, чем авторизует и
где расставлены грабли. Решений здесь нет намеренно — они принимаются
отдельно, после брейншторма. Спека коллектора Т-Банка, на которую всё время
идут ссылки: `docs/superpowers/specs/2026-09-01-tbank-collector-design.md`.

## 1. Как собирались факты

Живой личный кабинет владельца, отдельный чистый профиль браузера, только
чтение. Человек логинился сам; в форму входа не вмешивались. Структура ответов
извлекалась скриптом внутри страницы, чтобы значения не покидали браузер: в этом
документе нет ни сумм, ни описаний, ни идентификаторов — только имена полей,
типы и образцы формата с замаскированными символами (цифры → `9`, буквы → `a`).

Проверялось на выборке из 250 последних операций и двух счетах с двумя картами.
Всё, что ниже помечено как «не проверено», таковым и является.

## 2. Доступ к сайту: сертификат Минцифры

Весь домен Сбера выпущен через `Russian Trusted Sub CA`, корня которого нет ни
в хранилище Windows, ни в Chrome, ни в Firefox, ни во встроенном браузере.
Обычный Chromium отвечает `ERR_CERT_AUTHORITY_INVALID` и до банка не доходит.

Два рабочих пути, оба проверены:

- **Яндекс.Браузер** несёт корень Минцифры внутри себя. Playwright управляет им
  через `executablePath`, при этом хранилище ОС не трогается вовсе. Защита от
  второй копии работает по каталогу профиля, поэтому свой профиль поднимается
  даже когда у пользователя открыты собственные окна.
- **Node** — через `NODE_EXTRA_CA_CERTS` с корнем, скачанным с официальной точки
  раздачи Госуслуг (`gu-st.ru`, сам отдаётся под GlobalSign, то есть цепочка
  доверия выстраивается от общепризнанного УЦ).

Корень проверен делом, а не на слово: цепочка `web-node3.online.sberbank.ru`
валидируется им с `Verify return code: 0 (ok)`.

    Russian Trusted Root CA, действует до 2032-02-27
    SHA-256: D2:6D:2D:02:31:B7:C3:9F:92:CC:73:85:12:BA:54:10:35:19:E4:40:5D:68:B5:BD:70:3E:97:88:CA:8E:CF:31

Отсюда следует требование к любой будущей оболочке — десктопной или
мобильной: корень Минцифры придётся возить с собой и пинить, из коробки его нет
нигде.

## 3. Авторизация

### 3.1 Что установлено

Сессия держится **исключительно на куках**. Заголовка `Authorization` нет ни на
одном запросе, токена в query нет, `X-Requested-With` необязателен.

Из 23 кук, уходящих на API (7 из них `httpOnly`), нужны **ровно две**:

| Кука | Флаги | Домен | Срок |
|---|---|---|---|
| `UFS-SESSION` | `httpOnly`, `secure` | `.online.sberbank.ru` | сессионная |
| `UFS-TOKEN` | `httpOnly`, `secure` | `.online.sberbank.ru` | сессионная |

Установлено отбрасыванием по одной: без любой из этих двух — `403`, без любой
из остальных 21 — `200`. Ненужными оказались в том числе `JSESSIONID`, все
шесть кук F5 BIG-IP (`TS*`), куки Dynatrace, `sso_private_identification` и
`sbrf.pers_sign`.

Косвенное подтверждение из независимого источника: плагин Дзен-мани для Сбера
искал в ответе именно `UFS-SESSION` — в 2020 году и через мобильное API. Несущая
конструкция сессии не менялась шесть лет и пережила смену протокола.

### 3.2 Обычный HTTP-клиент банк пускает

Ключевой опыт: те же две куки, отправленные из Node **вне браузера**, дают
`200 success: true`. Заголовков достаточно трёх — `Accept`, `Content-Type`,
`Cookie`. Ни `User-Agent`, ни `Referer`, ни `Origin` не требуются: ветка с их
поочерёдным добавлением не понадобилась.

То есть отпечаток браузера на этом эндпоинте не проверяется, и схема Т-Банка
«человек логинится в окне → достаём секрет → дальше чистый HTTP» для Сбера
воспроизводима. Разница только в том, что секрет — две строки, а не одна.

`httpOnly` при этом не помеха: он закрывает доступ скриптам страницы, но не
владельцу cookie jar. Куки видят и `context.cookies()` в Playwright, и
`session.cookies` в Electron, и `CookieManager` на Android, и
`WKHTTPCookieStore` на iOS.

### 3.3 Профиль браузера сессию не хранит

Обе куки **сессионные**, и Chromium не пишет такие на диск. После закрытия окна
из профиля их уже не достать — проверено: повторное открытие того же профиля
дало 0 из 2.

Это ломает механизм хранения, который у Т-Банка работал даром. Там секрет жил в
персистентном профиле, где куки шифрует сам браузер средствами ОС, и отдельного
хранилища заводить не требовалось. Для Сбера так не выйдет: обе строки нужно
забирать сразу после входа и хранить самостоятельно, а вопрос «где именно и как
защищённо» становится отдельной задачей дизайна.

### 3.4 Не проверено

- **Срок жизни сессии.** Обе куки сессионные, без явного срока. Запущен замер
  почасовыми обращениями; он покажет жизнь **при лёгкой активности**, а не в
  простое — банк может продлевать сессию от самих обращений, как это делал
  Т-Банк. Виден эндпоинт `POST /api/warmUpSession`, похожий на явное продление.
- **Поведение антифрода на длинной дистанции.** Кабинет шлёт телеметрию на
  `bfds.sberbank.ru` и Dynatrace (`node6.vito.sber.ru`); коллектор её слать не
  будет. Один успешный запрос ничего не говорит о том, что будет через месяц
  ежедневных сборов.
- **Как выглядит вход.** Полный флоу авторизации не разбирался: человек входит
  сам, и воспроизводить это по HTTP всё равно не планируется.

## 4. Эндпоинты

Все данные отдаются по **POST**, а не GET. Хост данных —
`web-node3.online.sberbank.ru`.

| Что | Запрос |
|---|---|
| Счета, карты, кредиты, вклады | `POST /main-screen/rest/v2/m1/web/section/meta` `{withData, forceUpdate}` |
| История операций | `POST /uoh-bh/v1/operations/list` |
| Детали карты, включая долг по кредитке | `POST /ufs-carddetail/rest/card/v1/cardInfo` `{cardIds: [<число>]}` |
| Суммы по категориям | `POST /pfpv_alf_mb/v1.00/alf/amounts` |
| Настройки истории | `POST /uoh-bh/v1/history/configurations` |

Отдельно отмечено, потому что дорого узнавать заново: у `cardInfo` тело —
именно `{cardIds: [...]}`; на `{id: ...}` банк отвечает `500`.

Разделы «Кредиты» (`POST /person-credit/v1/loans/dashboard/landing`) и долг по
кредитке (`POST /credit_cards_dsib/web/v1/grace/efs/getCreditCardDebtsResults`)
возвращают **дерево UI-виджетов**, а не модель данных. Разбирать их хрупко и не
нужно: те же цифры лежат структурно в `cardInfo` (см. §6).

### Запрос истории

```
{ paginationOffset, paginationSize, showHidden,
  showNotTransactionBonuses, showOpenBanking,
  from, to, usedResource: [<строка>], filterName }
```

- `from` / `to` — формат строго `ДД.ММ.ГГГГTчч:мм:сс`. Точки без времени,
  ISO-8601 и epoch-миллисекунды дают `500`.
- `paginationSize` — до 250 включительно; на 300 приходит `500`. Пагинация
  обязательна, `paginationOffset` работает вглубь (проверено на 200).
- `usedResource` — фильтр по конкретной карте, значения вида `card:<16 цифр>`.

Ответ: `{success, body: {operations: [...]}}`.

## 5. Модель операции

| Поле | Тип | Смысл |
|---|---|---|
| `uohId` | UUID-строка | идентификатор операции; на 250 операциях уникален — **основа дедупа** |
| `date` | `ДД.ММ.ГГГГTчч:мм:сс` | **без указания зоны** |
| `operationAmount` | `{amount: число, currencyCode}` | сумма **со знаком** |
| `nationalAmount` | то же | в валюте счёта |
| `billingAmount` | `{id, name, amount, currencyCode}` | сумма списания |
| `description`, `correspondent` | строки | назначение и контрагент |
| `fromResource` / `toResource` | `{id, displayedValue}` | счёт операции, см. ниже |
| `form` | строка | **вид операции**, словарь банка |
| `type` | строка | `payment` или `ufsPayment` |
| `state` | `{name, category}` | `FINANCIAL`, `EXECUTED`, `AUTHORIZATION`, `UNAUTHORIZATION`, `REFUSED`; категории `executed` / `cancel` |
| `classificationCode` | число | MCC (но не всегда, см. §7) |
| `isFinancial` | boolean | `false` у заявок, не у операций |
| `externalId`, `authorizationDocId` | строки по 32 символа | совпадают примерно в половине случаев |

### Дата без зоны

Зоны в `date` нет. Косвенное подтверждение, что время московское: плагин
Дзен-мани разбирал такие даты, дописывая `+03:00`. Это то же допущение, что уже
принято для Т-Банка, и по той же причине: ночная операция, истолкованная как
UTC, уезжает на предыдущий день, а на границе месяца — в чужой месяц
статистики.

### Куда привязывать операцию

Правило вывелось чисто, на всех 250 операциях:

| Знак суммы | Где лежит счёт | Сколько |
|---|---|---|
| расход | `fromResource` | 210 |
| приход | `toResource` | 39 |
| суммы нет | нигде | 1 |

Единственная операция без суммы и без ресурсов — `UfsRefinancingClaim` с
`isFinancial: false`, то есть заявка, а не движение денег. Признак `isFinancial`
и отделяет одно от другого.

Важно: **знак несёт сама сумма**, а не отдельное поле направления. У Т-Банка
было наоборот — там знак задавался полем `type`.

### Словарь видов операций

`form` — то самое место, где живут слова конкретного банка. На 250 операциях
встретилось 14 значений:

    ExtCardPayment 134     покупка картой
    P2PSBPInTransfer 22    входящий перевод СБП
    UfsTransferSelf 21     перевод между своими счетами
    UfsQRSBP 18            оплата по QR через СБП
    ExtCardOtherOut 14
    UfsP2PSBPOutTransfer 13  исходящий перевод СБП
    ExtCardTransferIn 9
    ExtCardPaymentRefund 7   возврат покупки
    UfsTransferBankPartnerPhone 5
    ExtCardCashOut 3       снятие наличных
    UfsOutTransfer, UfsExtCardFee, UfsRefinancingClaim, ExtCardCashIn — по 1

Словарь ложится на виды операций приложения напрямую, включая переводы между
своими счетами. Плагин Дзен-мани в 2020 году опирался на **те же самые**
значения (`ExtCardTransferOut`, `ExtCardCashIn`/`Out`, `InternalPayment`), то
есть поле стабильно во времени.

## 6. Счета и карты

`section/meta` с `{withData: true}` отдаёт `body.sections.technicalSection.
sectionProductData` — блоки `accounts`, `cardsInWallet`, `ctaccounts`,
`depoAccounts`, `loans`, `investments`, `pensions`, `sharingCtAccounts`,
`obpctaccounts`, `ima`, `insurance`, `sberThanks`, `currencyRates`. У каждого
блока есть `state` (`SUCCESS` / `NOT_REQUESTED`) и `data`.

**Счёт** (`accounts.data[]`): `id` (число), `name`, `number` (20 знаков),
`balance {amount: строка, currency}`, `availCash`, `accountType`, `state`,
`rate`, `openDate`, `closeDate`.

**Карта** (`cardsInWallet.data[]`): `id` (число), `name`, `number`
(маскированный, вида `9999 99** **** 9999`), `cardAccount` — номер счёта карты,
`type` (`debit` / `credit`), `state`, `statusWay4`, `availableLimit`,
`availableTotalLimit`, `creditOwnSum`, `expireDate`, `cardCode`.

Карточные счета **не входят** в блок `accounts`: там лежат обычные и
накопительные счета, а связь карты со счётом даёт поле `cardAccount`. При этом
история операций привязана к картам, а не к счетам — на счетах своих операций
не оказалось вовсе.

**Кредитная карта.** `cardInfo` отдаёт в `creditType` всё нужное структурно и
строками: `creditLimit`, `creditOwnSum`, `creditDebt`, `creditMinPayment`,
`creditMinPaymentDate` (формат `ДД.ММ.ГГГГ`). Отдельный виджетный эндпоинт для
этого не нужен.

## 7. Грабли

**Деньги приходят и числом, и строкой.** `operationAmount.amount` — JSON-число;
`balance.amount`, лимиты и долг по кредитке — строки. Банк непоследователен
внутри собственного API, разбор обязан переживать оба варианта. Правило проекта
про `Decimal` и запрет `float` требует парсера, сохраняющего числовые литералы
как строки: обычный `JSON.parse` материализует число раньше, чем мы что-либо
проверим.

**Идентификаторы — тоже числа.** `id` счёта и карты приходят JSON-числами из 16
цифр, а граница безопасного целого в JS — `9007199254740991`, ровно 16 цифр.
Конкретные значения у владельца в диапазон укладываются, но полагаться на это
нельзя: разбирать без потерь нужно и идентификаторы, а не только суммы.

**Форма ответа плавает.** Одна операция из 250 пришла без `operationAmount` и с
лишним полем `ufsId`. У девяти `fromResource` присутствует, но содержит только
`displayedValue`, без `id`. Обращение к полям вслепую роняет разбор.

**`classificationCode` — MCC, но не всегда.** На 250 операциях 33 различных
значения, среди них узнаваемые `5411`, `5812`, `5541`, `6010`. Но попалось и
`99997668` — восьмизначное, к MCC отношения не имеющее. Проверка длины и
диапазона обязательна.

**Open Banking.** Флаг `showOpenBanking` в запросе истории и блок
`obpctaccounts` существуют, но у владельца пусты — проверить этот путь не на
чем.

## 8. Что можно взять у Дзен-мани

Плагин `sberbank-online` жил в открытом репозитории
[ZenPlugins](https://github.com/zenmoney/ZenPlugins) до мая 2020 года, потом был
удалён; сейчас там остался только `sberbank-by` (Беларусь). Исходники доступны в
истории. Он работал с мобильным API на порту 4477, то есть эндпоинты оттуда
неприменимы, а вот подходы полезны.

- **Транзакция как список движений.** Перевод между своими счетами — это два
  движения с общим идентификатором: расход на одном счёте, приход на другом.
  Разные валюты закрываются отдельным полем. Это ровно то, что в нашем проекте
  отложено под именем `transfer_group_id`.
- **Ключ склейки, когда видна только одна половина.** Для «Копилки» плагин
  выдавал `groupKeys` вида `дата_валюта_модульСуммы`, и пара сходилась позже.
- **Наличные как синтетический счёт.** `ExtCardCashIn`/`ExtCardCashOut` плюс
  regex по банкомату превращались в движение на счёт типа «наличные».
- **Счёт ищется по цепочке**: внутренний идентификатор → пара «валюта + хвост
  номера» → и только потом заглушка. Карты сворачиваются в счёт, накапливая
  список хвостов.
- **Неподтверждённые операции помечаются**: `hold` при `state = AUTHORIZATION`.
  У нас таких оказалось 11 из 250.
- **Недостоверный остаток честно помечается**: если сверка двух источников не
  сошлась, возвращается признак неоднозначности вместо неверного числа.
- **Секреты помечены для вычистки из логов** — у каждого запроса перечислены
  поля, которые нельзя писать в журнал.

И один антипример: их разбор денег — это `Number(строка)` с округлением до
копеек. Обычный `float`. Правилами нашего проекта это запрещено, копировать
нечего.

## 9. Чем Сбер отличается от Т-Банка

Сведено в одном месте, потому что от этих различий зависит форма коллектора.

| | Т-Банк | Сбер |
|---|---|---|
| Секрет | одна строка, самодостаточна | две куки, `httpOnly` |
| Где хранится | переживает в профиле браузера | профиль **не** хранит, нужно своё хранилище |
| Метод чтения данных | `GET` | `POST` |
| Пагинация | нет, 8285 операций одним ответом | обязательна, максимум 250 |
| Знак суммы | отдельное поле направления | в самой сумме |
| Счёт операции | одно поле | `fromResource` у расхода, `toResource` у прихода |
| Категория от банка | код категории банка | MCC в `classificationCode` |
| Сертификат | обычный УЦ | Минцифры, нужен свой корень |

Практическое следствие, которое стоит держать в голове при дизайне: allowlist
эндпоинтов остаётся возможным, но перестаёт быть **доказательством**
безвредности. У Т-Банка аргумент звучал как «в списке только GET, методом на
чтение ничего не сломать». У Сбера чтение идёт через POST, и эту часть гарантии
придётся либо заменить чем-то другим, либо честно признать утраченной.
